# RSS 使用指南

[返回项目首页](../README.md) · [部署说明](deployment.md)

机器人通过 RSSHub 获取动态并定时推送。订阅对象需要先加入可访问用户列表，由超管管理；群内所有成员可订阅、退订和修改本群推送配置。

## 配置平台与用户

首次部署并完成数据库迁移后，超管在群内 @ 机器人管理平台，无需手动修改数据库：

| 命令 | 用途 |
| --- | --- |
| `平台列表` | 查看平台名、路由前缀与翻译开关 |
| `增加平台 <平台名> <RSSHub路由前缀> <翻译0/1>` | 新增平台；已有平台不会被覆盖 |
| `修改平台 <平台名> <RSSHub路由前缀> <翻译0/1>` | 修改路由与翻译开关，保留平台名和用户关联 |
| `删除平台 <平台名>` | 删除未被任何用户引用的平台 |

示例：

```text
增加平台 twitter /twitter/user/ 1
平台列表
修改平台 twitter /twitter/user/ 0
```

平台信息仍保存在现有 `Plantform` 表中：

| 字段 | 内容 |
| --- | --- |
| `name` | 平台名，添加用户时使用同一名称 |
| `url` | RSSHub 路由前缀，末尾接用户 ID；从 [RSSHub 路由文档](https://docs.rsshub.app/) 查找 |
| `need_trans` | 是否需要翻译，`1` 为需要，`0` 为不需要 |

请求地址由 `RSSHUB_HOST + url + 用户ID` 拼接。路由前缀填写以 `/` 开头的相对路径，不含实例域名；通常以 `/` 结尾，也可使用 `/example?uid=` 这类将用户 ID 接在查询参数后的前缀。翻译只能填写 `0` 或 `1`。

平台名使用不含空格的名称。删除被引用的平台会被拒绝，需要先处理该平台的用户关联。

超管在群内添加用户：

```text
增加用户 <用户ID> <用户名> <平台名>
```

`用户ID` 是对应平台用于 RSSHub 路由的标识，例如账号 handle 或 UID；`用户名` 是展示名称。参数以空格分隔，用户名也请使用不含空格的名称。

## 群内命令

在群内 @ 机器人使用。`<参数>` 表示必填，`[参数]` 表示可选，不输入尖括号或方括号。

| 命令 | 用途 |
| --- | --- |
| `帮助` | 打开指令与按钮面板 |
| `用户列表` | 查看可订阅用户 |
| `rss <用户ID> [序号]` | 查看文章；序号默认 `0`，即最新文章 |
| `文章列表 <用户ID>` | 查看文章序号与标题 |
| `订阅` / `订阅面板 [页码]` | 打开订阅选择面板 |
| `订阅 <用户ID> [用户ID…]` | 订阅一个或多个用户 |
| `取消订阅` / `退订面板 [页码]` | 打开退订选择面板 |
| `取消订阅 <用户ID> [用户ID…]` | 退订一个或多个用户 |
| `查询 群组` | 查看本群订阅 |
| `群组配置` | 查看本群全部设置，不修改数据 |
| `群组配置 推送数量 <0-5>` | 每个账号每轮推送的最近篇数，默认 1；0 表示全部未发送 |
| `群组配置 <转发/自转发/翻译> <开/关>` | 单独修改本群对应开关，也可填 1/0 |
| `查看配置` | 查看本群设置 |

订阅与退订自动使用当前群 OpenID，无需在命令中填写群号或群 OpenID。多个用户 ID 用空格分隔。

### 群组配置

所有设置统一在 `群组配置` 下按名称修改，修改其中一项会保留其他设置。推送任务在每轮开始时读取配置，修改从下一轮刷新起生效：

| 设置项 | 默认值 | 含义 |
| --- | --- | --- |
| `推送数量` | `1` | 每个账号每轮只考虑 RSS 最新 N 篇；允许 1–5，0 表示所有未发送文章 |
| `转发` | `开` | 是否推送博主转发他人的动态 |
| `自转发` | `关` | 是否推送博主转发自己的动态，也可写 `自我转发` |
| `翻译` | `开` | 是否附带中文翻译，还需平台启用 `need_trans` 并配置翻译服务 |

例如：

```text
群组配置
群组配置 推送数量 1
群组配置 转发 开
群组配置 自转发 关
群组配置 翻译 开
```

篇数按每个账号、每个群独立计算，使用 RSS 的最新排列顺序。例如设置 2 时，只考虑最新两篇；其中已发送或被群开关过滤的文章不会用更旧的文章补足。窗口之外的旧文章静默登记，以后不补发。已有群数据库迁移后也默认为 1；可设置 0 恢复所有未发送文章的推送，但不会补发此前已静默登记的文章。

旧的 `群组配置 1 0 1` 仍按“转发、自转发、翻译”顺序修改三个开关，保留当前推送数量；旧第四项图片提示参数仍可填写，但不再生效。正文后直接发送所有独立原图，不再单独发送图片数量提示。

## 定时推送

定时任务每 `REFRESH_TIME` 分钟检查一次，默认 `20` 分钟，配置值必须大于 `0`。机器人需要在线；休息时段固定为北京时间 `02:00–08:00`，与容器系统时区无关。

每次启动时，`IF_FIRST_TIME_START` 默认为 `true`。首次刷新按群读取数据库中最近一次成功推送的时间：距离本轮开始超过 **20 分钟**，或该群没有成功推送记录时，该群本轮抓取到的文章只写入去重记录，不发送正文和图片；20 分钟以内（含恰好 20 分钟）则正常推送。时间依据是机器人的成功推送记录，不是文章发布时间。

首轮结束后标识自动变为 `false`，第二轮起不再进行这项时间检查，即使 `REFRESH_TIME=60` 也会正常推送新增文章。需要静默的订阅会先把待初始化状态保存到数据库；抓取失败时，下次首次有效抓取仍只登记历史文章。静默记录不算成功推送，也不更新上次成功推送时间。

超管可用 `/信号` 查看首轮检查标识；在首轮开始前执行 `/信号否`，可跳过本次启动的时间检查。启动静默优先于篇数配置；其他情况（包括后续新建订阅）均按该群推送数量处理。

每轮检查 RSS 返回的全部条目，为窗口外文章写入静默记录；只发送窗口内尚未处理的文章。全部正文页成功发送后才记录成功时间；失败正文仍在窗口内（或数量设为 0）时下一轮重试，一个群的失败不会中断其他群。初始化基线、窗口外文章和按群开关过滤的条目不计入发送统计。退订后再次订阅会沿用该用户与群的已有去重状态。

同一篇文章从多个订阅源出现时，群内成功送达一次即可；某来源跳过的历史文章或被过滤的文章，只影响该来源，不会阻止其他来源重试尚未送达的正文。

主 RSSHub 实例报错或无条目时依次尝试备用实例，取得有效内容即停止。翻译出错或超过 60 秒时发送原文；图片最多尝试四次。附件最终失败会尝试发送失败提示，并在日志中记录；已发送的正文不会因附件失败在下一轮重复推送。

正文使用紧凑的作者、时间和原文入口，保留完整原文与翻译；长文按段落分页，单段过长时继续按行、空白或字符边界拆分，不再截断正文。每篇先发完全部正文页，再逐张发送所有独立原图。

同一账号的各订阅群并行处理；每群有独立的文章队列，一篇的正文页与原图连续发完，其他 RSS 文章不能插入其中，手动 `rss` 查询也共用这把群锁和发送限速。每群两篇之间随机等待 5–15 秒；即使前一篇在部分正文页或发送记录写入时失败，下一篇仍会等待。同一账号的全部群处理完成后，再随机等待 5–15 秒处理下一个账号；最后一篇和最后一个账号之后不额外等待。

正文、图片及失败提示仍共用 QQ 发送限速，实际 API 调用串行完成后再等待下一个时隙。账号或图片很多时一轮刷新可能持续较久；手动与定时刷新共用锁，避免重复处理同一批文章。

可用 `查询 群组` 确认订阅，用超管命令 `refresh` 手动刷新；`refresh` 不受休息时段限制，但同样遵守启动首轮的时间检查。`rss <用户ID> [序号]` 可即时查看文章，不受定时去重记录影响。

旧版本若已把失败文章写入去重记录，更新后这些记录仍会保留，旧文章可用 `rss` 手动查看；后续新动态按修复后的流程推送。

### Docker 排查

代码或镜像发布后，需要更新正在运行的容器，步骤见 [部署说明](deployment.md#docker)。仅拉取代码不会更新容器内的程序。

```bash
docker compose logs --since 1h nonebot
```

检查 `任务开始`、`当前为休息时间`、`当前无订阅`、RSS 源错误及 `发送群 … RSS 正文失败` 等日志。若 RSS 抓取正常而 QQ 拒绝发送，需根据日志中的接口错误检查群内主动消息开关、机器人权限、群禁言和配额；这些运行状态不能仅由本地代码判断。

## 超管命令

在 `.env.prod` 或 `.env.dev` 的 `SUPERUSERS` 中配置成员 OpenID 后使用。

| 命令 | 用途 |
| --- | --- |
| `增加用户 <用户ID> <用户名> <平台名>` | 将用户加入可访问列表 |
| `删除用户 <用户ID>` | 从可访问列表删除用户 |
| `订阅列表` | 查看全部群的订阅 |
| `查询 群组 <群OpenID>` | 查看指定群订阅 |
| `查询 用户 <用户ID>` | 查看用户被哪些群订阅 |
| `订阅统计` / `发送统计` | 查看订阅与发送统计 |
| `群列表 [页码]` / `已加入群 [页码]` | 查看独立群登记表、入群时间及历史确认状态，每页 10 群 |
| `refresh` | 手动触发刷新 |
| `/发送 <内容>` | 向订阅群广播通知 |
| `/信号` / `/信号否` | 查看启动首轮检查标识 / 跳过尚未执行的首轮时间检查 |
| `清理失效订阅` | 查看由官方群事件维护的订阅状态 |

机器人被移出群时会通过官方事件自动清理该群订阅、配置和群登记。`清理失效订阅` 只报告登记差异；缺少登记不能证明退群，不会据此自动删除订阅。

### 群登记与入群时间

机器人通过独立的 `bot_group` 表维护已知所在群，不再用 RSS 订阅表代替群列表。群标识为官方 `group_openid`，不是数字 QQ 群号。

| 字段 | 内容 |
| --- | --- |
| `group_openid` | 群 OpenID，主键 |
| `joined_at` | 收到真实入群事件的时间；未知时为空 |
| `recorded_at` | 首次写入登记表的时间，不等同于入群时间 |
| `last_seen_at` | 最近一次收到入群/群消息事件的时间；历史未确认时为空 |
| `source` | `join` 入群事件、`message` 群消息确认、`history` 历史补录待确认 |

升级迁移会将现有 RSS 订阅群、群配置和存在时的生日群记录合并去重补录。历史群的真实入群时间无法从这些业务记录恢复，因此 `joined_at` 留空，不用迁移时间冒充。该补录只在迁移时执行，重启不会扫描旧表重新添加已删除的群。

收到普通群消息或 @ 消息后，未登记的群会自动补录，历史记录会确认；这不依赖是否订阅 RSS，也不受 RSS 忽略名单影响。私聊不会登记成群。收到入群事件时记录真实入群时间，后续普通消息不会覆盖它。收到退群事件时，群登记与 RSS 订阅/配置在同一事务中删除；再次入群则重新登记本次时间。

数据库时间统一保存为 UTC，`群列表` 和入群通知按北京时间显示。该表依赖实际收到的事件；无任何业务记录、也尚未收到消息的旧群无法凭空恢复，停机期间漏收的退群也不能通过此表独立核实。历史待确认记录会明确标识，发送失败或未收到群消息均不作为退群依据。

## 导入 X 关注

在与机器人的**私聊**中发送：

```text
导入关注 <群OpenID> <auth_token> <ct0> <X用户名>
```

从已登录 X 的浏览器开发者工具中，在 Application → Cookies 找到自己的 `auth_token` 和 `ct0`。机器人将关注列表与可访问用户匹配，再按返回的提示到目标群确认批量订阅。
